如果你留意过 AI 生成的文档、开源项目的 README、各种大模型的知识库，会发现一个共同点：它们几乎都用 Markdown（.md 文件）。不是 Word，不是 PDF，不是 HTML，甚至不是纯文本。为什么偏偏是 Markdown？这不是巧合，而是多个维度的比较之后，Markdown 成了 AI 时代最合适的“通用语言”。

<!-- more -->

## 一、它首先是纯文本：人和机器都能直接读

Markdown 的本质是纯文本文件。打开它不需要任何专用软件，记事本就能看，Git 能直接 diff，grep 能直接搜。

这对 AI 来说至关重要。AI 处理内容的第一步是把文件读成字符流。Word 的 .docx 其实是个压缩包，里面是一堆 XML；PDF 是排版指令和二进制的混合体；想从中提取正文，AI 得先解压、解析、还原，中间任何一步出错都会丢内容、乱顺序。而 Markdown 没有这层障碍——看到什么就是什么，零解码成本，零信息损耗。

**对比：**

| 格式 | AI 读取成本 | 是否无损 |
| --- | --- | --- |
| Markdown | 直接读 | 是 |
| 纯文本 .txt | 直接读 | 是，但无结构 |
| Word .docx | 需解压解析 XML | 常丢格式、错顺序 |
| PDF | 需解析排版指令 | 常丢表格、乱换行 |
| HTML | 需解析标签树 | 标签噪音大 |

纯文本是 AI 的母语，而 Markdown 是“带结构的纯文本”——这正是它胜过 .txt 的地方。

## 二、结构刚好够用：比 txt 多一点，比 HTML 少很多

AI 理解一篇文章，靠的是结构：哪里是标题、哪里是列表、哪里是代码、哪句是引用。Markdown 用最少的符号表达了这些结构：

- `#` 是标题，层级一目了然
- `-` 是列表，层级关系清晰
- `` ``` `` 是代码块，语言还能标注
- `>` 是引用，`** **` 是强调
- `[文字](链接)` 是超链接

这些标记同时满足了三方需求：人眼看着舒服、编辑器能渲染、AI 解析起来毫不费力。反观 HTML，表达同样一个标题要写 `<h1>标题</h1>`，标签比内容还多；表达一个表格更是一大坨 `<table><tr><td>`。这些标签对 AI 来说全是噪音——占 token、扰乱语义、还容易在生成时配对出错。

而纯文本 .txt 则走向了另一个极端：没有任何结构标记。标题和正文长得一样，列表和段落分不清，AI 只能靠猜。Markdown 恰好站在中间点：结构刚好够用，噪音几乎为零。

## 三、Token 经济学：同样的内容，Markdown 最省钱

大模型按 token 计费、按 token 限制上下文。格式的“啰嗦程度”直接决定成本。

同样一段带标题、列表和代码的内容：

- Markdown 版：标记只占内容的大约 5%~10%
- HTML 版：标签常常占到 30%~50%，表格更是翻倍
- Word 转出来的 XML：标记能比正文还多几倍
- JSON 版：引号、逗号、括号层层嵌套，结构信息占比更高

AI 每次读写文档都要为这些标记付 token。Markdown 的标记密度是所有富格式里最低的，等于用最少的钱传递最多的信息。而且因为语法极其简单，AI 生成时几乎不会写错；写 HTML 却很容易漏一个闭合标签，整个结构就崩了。

## 四、版本控制友好：diff 能看懂，协作才成立

AI 写东西不是一锤子买卖，而是反复改：改一段、补一句、调结构。这就离不开 Git 这样的版本控制。

Markdown 是按行组织的纯文本，改一行，diff 就只显示那一行，review 的人一眼看懂改了什么。Word 是二进制，diff 只能告诉你“文件变了”，具体改了哪句话完全看不出来；PDF 更不用说。AI 时代的写作大量发生在 GitHub、GitLab 和各种协作文档里，Markdown 是唯一能让“AI 改完、人能审、历史能查”同时成立的格式。

这也是为什么几乎所有开源项目都用 Markdown 写文档：README、贡献指南、变更日志，全是 .md。

## 五、生态惯性：AI 是在 Markdown 的海洋里长大的

还有一个常被忽略的原因：大模型的训练语料里，Markdown 无处不在。

GitHub 上数以亿计的 README 和文档是 Markdown；Stack Overflow、技术博客、官方文档大量使用 Markdown；很多数据集、评测集、提示词模板本身就是 Markdown 写的。AI 在训练中见过最多的结构化文本就是 Markdown，于是它写 Markdown 最熟练、最不容易出错——这是一种自我强化的循环：用得越多，模型越擅长；越擅长，就越多人用。

相比之下，reStructuredText（.rst）语法更强大，但在 Python 生态之外很少见；AsciiDoc 功能更全，但学习曲线陡、语料少；Org Mode 很强，但基本只活在 Emacs 用户手里。它们输给 Markdown 的不是功能，而是生态规模。

## 六、可移植与不过时：五十年后还能打开

Markdown 没有厂商、没有专利、不依赖任何软件。它就是带几个符号的文本文件。

Word 格式换过好几代，老 .doc 用新软件打开都会走样；Notion、飞书文档、Google Docs 的内容锁在平台里，导出一次丢一次格式；PDF 倒是稳定，但它是“写死”的排版结果，改起来极其痛苦。Markdown 写于 2004 年，二十多年过去，语法几乎没变过，任何一个文本编辑器都能打开，任何一门语言都有解析库。

对 AI 来说，这意味着知识可以长期沉淀：今天生成的 Markdown 笔记、文档、博客，十年后不需要任何迁移就能继续用、继续被更新的模型读懂。

## 七、生成友好：AI 写 Markdown 几乎不犯错

最后一点很实际：Markdown 对生成式 AI 特别友好。

- 语法只有十几个符号，模型几乎不会写错；
- 不需要配对闭合标签，没有 HTML 那种“一处错、全篇崩”的风险；
- 格式和内容可以一遍生成，不用先写内容再套样式；
- 出错也容易修：少一个 `#` 只是少一级标题，不会破坏全文。

而让 AI 直接生成 Word 或 PDF，等于让它在写文章的同时还要当排版引擎——字体、页边距、分页符，错一个就全乱。正确的做法永远是：AI 写 Markdown，需要时再由工具转成 Word、PDF 或网页。Markdown 是“源格式”，其他格式是“输出格式”。

## 一张表总结

| 维度 | Markdown | Word | PDF | HTML | 纯文本 |
| --- | --- | --- | --- | --- | --- |
| 人可读 | 好 | 好 | 好 | 差 | 好 |
| 机器可读 | 极好 | 差 | 差 | 中 | 好 |
| 结构表达 | 够用 | 强 | 弱 | 强 | 无 |
| Token 效率 | 高 | 低 | 低 | 低 | 最高 |
| Git diff | 清晰 | 不可用 | 不可用 | 尚可 | 清晰 |
| 跨平台 | 完全 | 依赖软件 | 只读为主 | 需浏览器 | 完全 |
| 生成容错 | 高 | 低 | 低 | 中 | 高 |
| 生态规模 | 巨大 | 大 | 大 | 巨大 | 小 |

## 结语

AI 选择 Markdown，不是因为它功能最强——论排版它不如 Word，论表现力它不如 HTML，论严谨它不如 LaTeX。而是因为它在所有关键维度上都拿到了“足够好”，同时在成本、简洁性和通用性上无人能及。

它像一张白纸，只多了几道折痕：不多不少，刚好让机器和人都知道哪里该分段、哪里是重点。在 AI 成为主要内容生产者的今天，这种“对人和机器都友好”的格式，注定是默认选项。

下次当你让 AI 写点什么，不妨直接说一句：用 Markdown 写。它本来就想这么干。
